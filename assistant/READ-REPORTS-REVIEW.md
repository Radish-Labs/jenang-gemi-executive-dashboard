## Read-only and privacy checks

- The production business reader creates explicit analytics/SKU/partner connections, pins the analytics target, disables multiple statements, requires a read-only repeatable-read transaction, applies a statement timeout, and rolls back in `finally`. Shared helpers receive these connections rather than opening a default global connection.
- The inspected MCP paths use passive canonical helpers with schema preparation disabled. The extracted accounting and analytics service files define functions without running a cache refresh, provider request, migration, or write when included. Legacy interactive mutating wrappers remain separate; the MCP selects their read variants.
- Missing required source tables/columns fail through the source-tagged connection wrapper. Cross-database failures preserve which source failed without returning SQL, raw table errors, credentials, or private rows. Required-source failures are not represented as zero activity.
- `customer_retention` restricts sources to configured accounts before identity processing and projects only aggregate counts, rates, lifecycle segments, channel totals, and month trends. Customer names, phone numbers, addresses, order IDs, provider payloads, and canonical customer profiles do not leave the adapter. Fixtures verify private markers are absent and foreign-account values do not affect its totals.
- Overview and cash projections omit vendor/contact identities, notes, actors, payment proofs, and receipt references. Company accounting labels remain untrusted business text. Their existence is not authority to act on instructions contained in those labels.
- Freshness metadata distinguishes read time and stored activity from verified upstream synchronization. Current cash state, unpaid commitments, cash flow, accounting P&L inputs, and recipient allocation remain separate concepts. Cross-database reads do not claim an atomic snapshot or a reconciled month close.

### Disabled ingestion bridge review

Reviewed `ingest-reports.php`, its tool descriptor and central RPC/catalog integration. The bridge pins all twelve reviewed upstream schema definitions; ten account sources are implemented, while global sync runs and worker runtime remain denied because no explicit authorization binding covers those complete organizational sources. A broad dashboard grant or all current account keys does not override this restriction.

The ordinary execution path stops at `INGEST_REPORTS_SOURCE_RELEASED=false` before resolving service configuration or opening a connection. The internal fixture seam requires both injected settings and transport closures, neither of which is an RPC argument. When released, the transport is a fixed HTTPS GET with header-only service authentication, verified TLS, no redirects, a timeout and a 2-MiB response limit. No URL, method, SQL, header or credential is user-selectable. No source refresh, schema preparation, token renewal, job action or ad mutation is performed.

Argument authorization precedes transport. Projection checks the exact source, account/platform, query echo, grain, date basis, pagination and coverage; it emits only pinned typed fields. Global sources are also rejected in direct projection. Private unexpected fields and upstream prose are dropped, and raw upstream errors are replaced by fixed reason codes. Monitor actor remains unknown, source transition time/reason remain unavailable, and aged monitoring snapshots cannot retain current observations or verified incidents. The final serialized projection has its own 2-MiB limit. Missing, denied, unpublished and stale sources stay distinct from zero activity.

The tool schema's initially advertised null filter value was removed to match scalar-only runtime validation. Final bridge fixtures passed **384 checks** and central dispatch passed **27 checks**: **411 additional checks**. These include all account source/view combinations, exact money/IDs, global and account denials, stale monitor behavior, privacy, bounded pagination, input/output size and the disabled release gate. The bridge owner separately verified all twelve pinned definitions against the upstream checked-in contract. No authenticated hosted source query was performed by this review.

No production request, live business write, grant change, credential operation, deployment or metadata refresh was performed in this review. No review action was denied or has an uncertain outcome. Production MySQL/MariaDB behavior, source freshness/completeness and callable client discovery remain release verification work.
